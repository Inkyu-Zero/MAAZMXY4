# 游戏数据库与地图识别（开发版）

本轮实现面向下一版本，完成源码、编译和离线检查，尚未启动测试客户端或连接真实游戏验收。没有发布新 Release、EXE 或更新清单。

## 游戏数据库

左侧新增“游戏数据库”，不需要连接游戏。支持名称、材料、掉落地点、技能关键词查询，多个关键词用空格组合；可以按装备、道具、Boss 及子分类筛选。精确名称优先，每页最多 60 条，点击条目查看详情。窄窗口会把结果列表放在详情上方。

本次整理于 2026-10-29：787 条装备、1,167 条道具、231 条 Boss，共 2,185 条；包含 1,367 张道具/装备图标。全部 Boss 条目保留官方技能或战斗机制说明。三项图标在官方资源服务器返回 404，相关条目仍可查文字。没有用其他道具的图片替代。

资料采用顺序：

1. [4399 电脑版装备图鉴](https://news.4399.com/gonglue/zmxy4/zhuangbei/)、[道具图鉴](https://news.4399.com/gonglue/zmxy4/daoju/)、[Boss 图鉴](https://news.4399.com/gonglue/zmxy4/boss/)。保留属性、配方、获取地点、技能事实及页面日期，不纳入评论、广告或背景故事。
2. [社区帮助文档](https://rotating-stars.github.io/zmxy4-helpPages/)及其[公开源码](https://github.com/Rotating-stars/zmxy4-helpPages)，固定提交 `669191e883342cd6af9cb5410a46322691a9a1d0`。关联 38 个资料页、136 个条目，并补充 92 个条目的表格。保留 MIT 声明。该站是社区资料，未标作官方 wiki。
3. 本地只读研究工程与官方客户端配置作补充。当前官方入口引用的版本为 `v.20261019.00:01`，配置 SHA-256 为 `57139ad6c4cac1476f57b165cdd9d6fdc4b4aab61ce0e1905cfa8b253da9e45c`。1,762 个条目附有配置资料；同名 Boss 的不同记录、等级、位置分别展示。它们是基准值，不是承诺的实战结算值。

数据文件保留配置原值；界面将命中、暴击、闪避、魔抗、破魔、韧性、魂击率和标明“比例”的增幅统一显示为百分比，并将区间显示为“～”。属性正文与强化属性也遵循相同规则；已带 % 的数值不重复换算，生命、攻击等绝对数值保持原单位。官方图鉴、社区表格和客户端配置按来源分别展示，不静默覆盖冲突。缺失数值显示为来源未提供。旧活动获取方式可能已变化，详情提供来源页面供核对。

获取方式、用途及配方中的材料或装备名称可直接跳转到本地百科条目，并可返回上一条目；搜索条件保持不变。没有可关联条目的获取或用途说明提供来源链接。正文使用 15px 字号和 25px 行高，链接使用原生 HyperlinkButton，支持键盘焦点和换行。

事实字段可包含 `links: [{"text":"七彩晶","target":"entry:条目标识"}]`。目标也可使用已验证来源的 HTTPS URL；内部跳转只按稳定标识解析，不猜测重名条目。导入器保留官方表格中的链接，`tools/research/catalog_links.py` 为唯一同名材料建立离线关联。链接之外的原文、来源哈希与原始数值不变。

检索过的 TapTap、`zmxyol2` 图鉴属于手机版；视游的“wiki”栏目混有手游说明，未用来覆盖电脑版事实。没有找到可稳定核验的专门 BWiki/灰机电脑版数据库，未将搜索结果数量当成来源可靠性的依据。

数据在 `agent/data/game_database/`，自动进入现有资源/完整包收集流程。页面使用宿主 Avalonia/DI/侧栏，首次打开异步载入一次，检索文本预先建立，输入防抖 160 ms，分页控制列表数量，图标仅在选中时读取并释放；没有额外 Python 工作进程、网络轮询或游戏控制器。

## 两个 SWF 与素材提取

入口为 [AperturePlus/ZaoMengXiYou-4](https://github.com/AperturePlus/ZaoMengXiYou-4) 历史提交 `86a00f893f19f19b38754e5d9a062c05f00f4864` 的两个 SWF。文件与 SHA-256 在 `tools/research/swf-sources.json`。

使用 [JPEXS FFDec 26.4.0](https://github.com/jindrapetrik/jpexs-decompiler/releases/tag/version26.4.0) 命令行导出，没有运行 SWF。主文件导出 13 张位图、101 个矢量形状、488 个精灵帧和 3,522 个脚本；启动器导出 38 个形状、62 个精灵帧和 86 个脚本。两个内嵌 SWF 另导出 10 张位图、15 个形状、9 个精灵帧与 28 个按钮状态。

主文件的 `AssetsURL` 明确把装备/道具图片放在外部 `assets/icon/prop/`，地图通过资源清单加载。两份历史主程序不含完整图标库。因此继续只读获取其引用的官方资源清单，并沿当前公开游戏入口核对到 2026-10-19 清单，用实际地图 SWF 和 XML 资源映射补全。CDN 的“访问错误”SWF 与有效资源会同样返回 HTTP 200，研究过程校验内容与哈希，不把错误页作为地图素材。

原始 SWF、反编译代码、完整配置、网页缓存和工具不进入运行包；仅保留功能需要的图标、识别裁剪、来源摘要和事实表。游戏素材权利仍归原权利人，项目代码许可证不改变这些素材的权利归属。

离线开发入口（参数使用自己的外部研究目录）：

```text
python tools/research/export_swf_assets.py --input-dir <历史SWF目录> --ffdec-jar <ffdec.jar> --output <新导出目录> --scripts
python tools/research/unpack_game_config.py <配置容器> <新配置目录>
python tools/research/import_stage_variants.py <含manifest和FFDec导出的地图目录>
python tools/research/import_battle_ui_assets.py <含manifest和官方弹窗SWF的目录> --ffdec-jar <ffdec.jar> --fixtures
python tools/research/import_game_catalog.py --cache <网页缓存> --output <官方事实JSON>
python tools/research/enrich_game_catalog.py --catalog <官方事实JSON> --assets <官方资源目录> --wiki <社区资料仓库> --output agent/data/game_database --icon-cache <外部图标缓存>
```

研究工具额外使用 BeautifulSoup、requests、Pillow、numpy；这些不是新增加的客户端运行依赖。`mod/mo2` 容器复用标准 DEFLATE 解包，AMF 项保存为不透明数据，不执行 ActionScript。

## 地图识别

SWF 的 `MovieClipButton` 显示：第 1 帧为普通，第 2 帧为首次可进入，第 3 帧为悬停。对七个已有普通刷关入口导出实际状态，按 placement scale 和短边 720 缩放，再裁取 alpha ≥ 235 的内部区域。删除重复状态后共 17 张模板，来源、字符 ID、裁剪、缩放和哈希记录在 `agent/data/navigation/stage-variants.json`。

复用 MaaFramework 的 `And`、`Or` 和 `TemplateMatch`：先确认地图“任务”按钮，先尝试已有截图模板，未命中时再尝试多状态素材。点击使用对应识别框，未知地图继续安全停止。保留导航图的遮挡关系、真实到达确认、悬赏独立路径和失败预算，不通过移动真实鼠标或盲点坐标消除高亮。

参考了 [MAA 任务协议](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/master/docs/zh-cn/protocol/task-schema.md) 的 ROI/模板复用思想，以及 [MaaEnd](https://github.com/MaaEnd/MaaEnd) 和本项目共同使用的 MaaFramework。没有引入另一套识别或输入框架。运行节点遵循项目固定的 Maa 版本；网上的新协议字段没有直接升级进客户端。

## 复活提示与战斗返回

全部 11 个现有战斗任务接入自动拒绝还魂丹/免费复活提示。回放中的监测线程只做识别，发现提示后由原回放线程释放按键和鼠标，再交给 Maa 原生节点识别并点击“取消”。拒绝后必须看到实际失败画面，才按原有失败规则处理；失败不计成功次数，重试开关及每轮预算保持原语义。生成器同时修复“重试次数为 0”被覆盖的问题，并检查重复生成不改变文件。

回放结束、设置退出和导航起始流程也处理该弹窗。标题出现而按钮布局尚未稳定时，进入有时限的等待；画面未知或操作失败时停止，不点击背后的设置或返回控件。普通/免费提示、单人/双人布局、普通/悬停/按下状态来自官方复活模块，共 12 个组合。取消操作确认窗口身份、尺寸及按钮排列后，使用相对窗口的固定点击位置；不再匹配取消小字或倒计时。成功和失败的返回按钮各补入三种状态，保留原截图模板和对应结果标题校验。14 张运行裁剪的来源、哈希及取消位置标定在 `agent/data/navigation/battle-ui.json`。

复用原生匹配时发现，Maa 的组合识别引用只读取子节点的识别参数，不应用其顶层 `inverse`；接口缓存还可能保留反转前的结果。对照[框架识别实现](https://github.com/MaaXYZ/MaaFramework/blob/0fc6025c2fc224a171b57d89505e8d47acd2a8b1/source/MaaFramework/Task/Component/Recognizer.cpp)后，使用一层同帧无弹窗判断包装原生匹配，资源缺失或异常时拒绝返回。没有增加截图线程、图像匹配引擎或输入执行器。

## 性能与验证边界

`task_catalog.read_document()` 对普通 JSON 直接使用标准解码器，只有 JSONC 进入逐字符注释扫描。不缓存用户实例配置，下一次读取仍可见修改。20 次同机测量，资源配置加载中位耗时约 105.0 → 9.0 ms；这只说明配置解析路径的改善，不能推断为整机 CPU 或鼠标延迟的改善。可用 `python tools/benchmark_task_config.py` 重测。

本轮离线验证覆盖：

- 前端完整编译；数据库 Headless 查询、材料关联、分页、失败重试、窄窗口和计时器释放；深浅主题离屏渲染。
- 七关卡各三种状态的 21 张独立合成画面，Maa 原生识别逐一排除另外六个关卡；去掉地图按钮后拒绝识别。夹具明确标记为合成图片。
- 已有导航图/运行逻辑和四项原生内存控制器回归；任务 JSON/JSONC 语义及新导入器格式回归。
- 数据与图标哈希、来源、实际资源包文件收集；不把未执行的安装测试算作通过。
- 12 个复活弹窗组合、6 个返回按钮状态及缺标题/缺按钮/背景结果负例；真实 Agent IPC 配合内存控制器检查正常回放、失败中断、先释放按键再取消、跨进程无弹窗判断，未连接真实窗口。

原仓库的通用 interface schema 不认识已有的 `repeatable/repeat_count` 宿主扩展；这两项及 `assets/interface.json` 本轮未修改。所有变更后的 Pipeline 通过仓库 schema 校验。没有删掉重复计次字段来绕过检查。

下一步实机验收需另行授权：新客户端的侧栏/主题、运行任务时查库、搜索与来源链接；七关卡普通/悬停/首次可进入及鼠标覆盖图标；地图滚动、分辨率变化、错误地图和覆盖层负例；还魂丹和免费复活提示的取消、倒计时及失败返回；用户录制与绑定保留。之后才进入候选打包、干净安装、升级及真实发布资产验证。

## 后续素材细化（2026-10-29）

共享确认框和设置窗口的新增来源、裁剪、源帧哈希及产物哈希分别记录在 `agent/data/navigation/common-ui.json`、`settings-ui.json`。开发导入器为 `tools/research/import_common_dialog.py` 和 `import_settings_ui.py`。结算完整显示列表由 `render_result_states.py` 冻结到稳定帧后交给 FFDec 导出，不执行 Flash 代码。42 张角色/结果/按钮组合保存在测试目录，原生运行仍只使用小型标题、按钮和边框模板。

源文件显示，第 1 帧也可能用于不可进入的关卡；`enabled` 只改变鼠标事件，不一定改变外观。因此识别到图标不代表已解锁，必须继续确认真实入场场景，不以图标差分猜测权限。图标暂时缺失时的只读等待、浮窗阻断、设置菜单定位及离线性能记录见[导航细化说明](通用导航迁移与失败重试说明.md#2026-10-29-素材覆盖与导航细化)。本轮新增验证未覆盖血海像素与实机操作。
