# 后台点击与孤魂岭事件修复

记录日期：2026-11-07。本文区分真实游戏取证、隔离实验和实现；小样本不代表长期成功率。

## 已确认的原因

失败时，AIR **完整收到按下和抬起，但两者命中了不同的内部对象**。相同屏幕坐标、相同外层关卡按钮，不代表相同的鼠标事件目标。因而没有生成 CLICK，按钮的 `onClick`、地图的 `onBtnClick`、`goToDungeon(47)` 均未执行。此次样本不支持“进关请求已发出但被服务器拒绝”。

```text
MAA 向已绑定窗口发送后台 WM_MOUSEMOVE
 → AIR 调用 TrackMouseEvent(TME_LEAVE)
 → 真实鼠标在其他窗口，Windows 投递 WM_MOUSELEAVE
 → AIR 发出 mouseOut(-1,-1)，按钮切回普通帧
 → DOWN 命中普通帧的子 MovieClip A
 → AIR 重新产生 mouseOver，切到悬停帧，换成子 MovieClip B
 → UP 命中 B；A ≠ B，没有 CLICK，也没有进关回调
```

真实失败样本的额外 OUT 在 DOWN **之前约 8～15ms**，不是都在按住期间。高亮、悬浮说明只能证明发生过 OVER，不能证明 DOWN/UP 目标一致。此次目标父链始终属于关卡按钮，也不支持“提示窗抢走 UP”。

游戏 `MovieClipButton` 构造设 `mouseChildren=false`，但 `enabled(true)` 又把 `mouseEnabled` 和 `mouseChildren` 一起设为 true。`TownMapMediator.updateTown` 会启用已解锁入口；`onMouserOut` 切第 1 帧，`onMouserOver` 切第 3 帧。孤魂岭两帧中的子 MovieClip 是不同交互对象。失败 DOWN 类为 `town5_20260202_1_fla::_1047_1_4`，UP 类为 `town5_20260202_1_fla::_1047_3_7`，外层始终是同一 `s47`。

本机 AIR 51.2.2.6 的 TrackMouseEvent 调用位于 DLL RVA `0x44A950`，返回位置 `0x44A956`，函数范围 `[0x44959C,0x44B773)`。这是当前版本的定位证据；**正式实现不使用这些偏移，不修改 AIR 导入表**。

## 用户观察与证据

| 现象 | 解释及局限 |
| --- | --- |
| 二倍速容易失败，一倍速偶发 | 二倍速现场为 60fps，更容易在按下与抬起间完成对象切换。时序影响触发概率，不是此次样本中输入未送达。 |
| 前四张地图没有同样问题 | 素材核对：前四图常规入口内部是 Shape，第五图 16 个入口内部是 Sprite；Shape 不作为独立鼠标交互目标，前四图更容易保持外层 target 稳定。 |
| 幕山正常 | 用户复测及 MAA 场景识别确认成功；当时已换到没有探针的新进程，未取得幕山真实 DOWN/UP 对象日志。 |
| 真鼠标放在入口后明显改善 | 不易再触发真实光标在窗口外的额外 LEAVE，与取证链一致。 |
| 缩短按压、双击没有改善 | 每次 MOVE 都可能重新注册追踪，重复点击可能重复同一失败链，不是次数够多就必定成功。 |

真实游戏共关联 9 对 DOWN/UP：3 对同一 target，产生 CLICK 并调用 `goToDungeon(47)`；6 对 target 不同，无 CLICK、无进关回调，分布在三组双击中。日志开销可能影响概率，不能据此推算长期成功率。

## 方案取舍

| 方案 | 修改面、难度 | 效果与副作用 |
| --- | --- | --- |
| 缩短按压、增加连点 | MAA 参数，低 | 已试未解决，不能保证同一 target。 |
| 外部取消 TrackMouseEvent | MAA 调用，低 | MOVE 前后取消均返回成功但仍失败；AIR 可重新注册，也不能可靠撤回已入队 LEAVE。 |
| 移动真实光标/抢焦点 | MAA 输入，中 | 用户观察到改善，但干扰其他窗口，不符合纯后台要求。 |
| 固定按钮交互对象 | 游戏 mouseChildren 或稳定 hitArea，中 | 从按钮本身解决，但要改游戏资源并适配更新，不属此次修改范围。 |
| 过滤目标线程的队列 LEAVE | MAA 原生模块与输入生命周期，中 | 本次采用。Windows 钩子在目标游戏进程内执行 MAA 附带 DLL；无需修改 zmBox、SWF、AIR 磁盘文件或移动真实鼠标。 |
| 永久伪造光标查询 | 多个 API 与应用行为，高 | GetCursorPos 等是 API，不是窗口消息；全部拦截会扩大到拖拽、菜单、手动操作，缺少必要性证据，本次不采用。 |

## 实现与边界

入口是 `agent/background_mouse_guard.py`，原生实现为 `native/background_mouse_guard/guard.cpp`，加载路径为 `runtimes/win-x64/native/MaaBackgroundMouseGuard.dll`。

1. 使用控制器已绑定的 HWND，核验 `ApolloRuntimeContentWindow`、PID、线程，保留目标进程句柄。非 AIR/内存控制器保持原行为。
2. 对目标加互斥租约，拒绝另一输入所有者及重复获取；记录所有者 PID 和创建时间，避免 PID 重用误认。
3. 安装线程级 WH_GETMESSAGE，由目标内 DLL 确认握手及 `Adobe AIR.dll` 已加载，再允许输入。缺模块、无效窗口、权限/位数不兼容或握手失败会报错，不静默退回旧行为。
4. 仅在租约有效、同一窗口、PM_REMOVE 出队时，把 WM_MOUSELEAVE 改为 WM_NULL。移动、按下、抬起、滚轮、键盘和其他窗口消息继续传递。直接 SendMessage 的 LEAVE 不属队列过滤范围。
5. `Navigator.perform` 的完整原生操作（含 repeat、post_delay）持有租约。普通战斗回放与通用播放在完整录制、输入释放、悬停清理期间持有租约，不改坐标、录制时间线或倍速参数。
6. 结束前等待排在已投递输入之后的队列标记，避免 PostMessage 的 UP 尚未处理就撤销保护。开始握手和结束出队确认各有 1 秒上限；超时仍清理并返回错误。
7. finally 释放租约、卸载钩子。过滤过 LEAVE 且真实鼠标仍在窗口外时，补一次离开通知恢复正常悬停。停止、异常、目标退出均清理；所有者崩溃后存活检查不再允许过滤，后续所有者可重新获取。

覆盖本次孤魂岭入口、公共导航、普通战斗回放和通用播放；不在空闲、识别、录制监听或整个任务队列期间永久保持假悬停。生存大冒险、九转炼丹等独立自定义点击路径未因本次问题扩大改动，也未修改 MaaFramework 全局输入。

“保持小助手安排的位置”在此指：受保护操作期间，不让已确认的系统离开通知清掉 AIR 后台悬停状态，**不是伪造所有光标 API**。如果用户同时在游戏客户区手动移动或点击，真实 MOVE/DOWN/UP 仍会进入游戏；其他窗口操作不被本模块拦截。不能承诺不存在所有应用交互影响。

现有入口 1 倍 100ms / 2 倍 50ms、地图主线双击及移开悬停规则保留。本修复不涉及玉兔儿技能冷却、动作状态、键盘接受规则，不能据此声称修复所有技能未释放问题。

## 验证与证据

隔离程序使用实际按钮类/素材及同一 AIR 运行库，不加载游戏业务或登录账号。早先诊断过滤为 3/10 → 10/10 → 5/10 CLICK（原始→过滤→撤销）；加入出队确认的正式实现复测为 **5/10 → 10/10 → 4/10**，过滤期间额外 OUT 为 0。均保留 60fps、50ms 按压、50ms 双击间隔，不调用真实鼠标移动或焦点切换 API。最终模块的队列清理及安装验证结果随本地交付记录保存。

回归入口：

- `tests/test_background_mouse_guard.py`：开始失败不输入、异常/取消释放、清理失败不报成功、非 AIR 保持行为。
- `tests/test_background_mouse_guard_native.py`：独立隐藏窗口跨进程验证目标过滤、其他消息放行、撤销恢复、所有者冲突/崩溃、目标退出和队列出队确认。
- `tests/test_navigation_runtime.py`、`tests/test_script_playback.py`、`tests/test_battle_player_studio.py`：接入生命周期及原回放行为。
- `tests/test_release_package.py`：缺少模块、过期源码摘要、DLL 篡改均阻止完整包生成。

本机证据位于发布树外的 `asset-references/live-entry-events-20261107/`、`air-native-leave-20261107/`、`background-mouse-guard-20261107/`。日志、游戏素材和本机测试文件不进入公开客户端。真实孤魂岭修复后的连续进关效果仍需用户复测，不能把隔离结果写成真实游戏验收。

本轮使用本地包内 Python 执行上述相关检查，共 113 项通过，含原生跨进程钩子、Maa 内存控制器及真实 Agent IPC；没有启动日常小助手任务。另编译仅关闭过滤分支的隔离对照 DLL，目标消息回归按预期失败（额外 LEAVE 到达窗口），证明回归确实覆盖过滤行为。该对照 DLL 和假的 AIR 测试模块不安装到日常客户端。

## 构建与回滚

用 x64 MSVC 运行 `tools/build_mouse_guard.ps1 -OutputDirectory <源码树外目录>`，产出 DLL 和 `mouse-guard-build.json`，记录协议、架构、源码、构建脚本、二进制 SHA-256，使用静态 C++ 运行库。`tools/build_release.py --client --mouse-guard <该目录> ...` 将两者放入固定 native 目录；打包校验当前源码及摘要，`--verify-client` 校验最终文件摘要。无需重编译 Avalonia。

安装前停止小助手，备份本次替换程序与用户数据，再原子替换；仅更新旧摘要相符的安装清单条目，新文件单独记录。回滚需同时恢复本轮 Python 接入文件及原生模块，不能只删 DLL。构建产物以外的诊断探针和测试 stub 不得进入日常客户端。

官方语义：[WM_MOUSELEAVE](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseleave)、[GetMsgProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/getmsgproc)、[SetWindowsHookExW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw)。
