# 通用导航与失败重试

## 全主线任务资源

新增的普通主线范围为南瞻部洲 16 关、东胜神洲 13 关、北俱芦洲 10 关、西牛贺洲 7 关和幽冥血海 16 关，共 62 关。它们保留在任务定义中，通过 `default_add: false` 仅供“＋”添加；省略字段的旧任务保持原有加载行为，手动添加、删除和已选状态不会被自动补全覆盖。

`tools/research/import_mainline_stages.py` 从离线缓存的 Dungeon 配置和五张地图 SWF 中提取按钮三态，排除固定工具栏遮挡，生成 `agent/data/navigation/mainline-stages.json` 与局部模板。入口同时核对洲、普通模式和遮挡，输入使用当前帧匹配框。血海 16 关只配置左右端点及既有拖动节点，不增加偏移估算或另一个导航器。

`tools/research/cache_mainline_maps.py` 沿离线版 `AssetsURL.getMapURL`、`GoInBattleCmd` 的资源引用缓存原始 SWF、DAT 和动画素材，并保存 URL、大小及 SHA-256；原始素材不随助手分发。`import_mainline_scenes.py` 根据关卡配置、碰撞地形及图层布局提取两处局部场景特征，检查不同动画相位并避开外部动画区域。普陀山脚和九龙宝殿的开场背景共用素材，识别等价关系明确记录；运行时必须先核对并点击各自入口，不能单凭共同背景选择任务。首次剧情画面不属于刷取模板。

生成顺序为 `tools/build_script_tasks.py`、`tools/build_navigation.py`。62 个新任务各声明开始、计数、入口和场景/播放四个节点，统一调用现有 `script_task_state`，不复制战败、返回或重启链路。大量资源定义不意味着全库识别；每轮只激活当前任务的候选，图像处理留在原生 Maa ROI 中。

离线素材测试入口为 `test_mainline_tasks.py`、`test_mainline_native.py` 和 `test_mainline_transport.py`。后两项需要显式设置 `MAINLINE_ASSET_SOURCE`（地图 SWF 导出目录）、`MAINLINE_SCENE_FIXTURES`（离线合成场景目录）以及相应的原生测试开关。它们使用内存控制器，不连接游戏。合成素材验证不能替代所有设备、角色、动画状态的实机验收。

不周山的场景核验改用两处静态地形，保持 0.83 阈值和原有浮窗守卫。原模板覆盖中央人物、剑阵动画，实际进关后会因动画变化而一直无法确认场景。场景提取器现将已识别的多帧精灵区域加入不稳定遮罩，不能以三个导出采样点相似就将其视为静态背景；静态不透明前景覆盖的区域仍可使用。可用 `import_mainline_scenes.py <离线素材目录> --evidence <树外证据目录> --stage-id 46` 只重生成本关，再依次执行 `tools/build_script_tasks.py`、`tools/build_navigation.py`，其余关卡资源保持原值。

`test_mainline_scene_regressions.py` 覆盖动画遮罩、局部重生成、两张已遮挡个人信息的不周山失败截图及错误画面拒绝；设置 `NAVIGATION_NATIVE_TESTS=1` 执行原生识别，额外配置 `MAINLINE_SCENE_FIXTURES` 可核对全部 62 关场景。`test_mainline_transport.py` 的不周山专项覆盖两种真实动画画面经 Agent IPC 完成一轮、错误场景不执行录制。检查均为内存控制器离线验证，不代表已更新日常客户端或完成实机验收。

## 鼠标悬停处理

普通关卡在已确认的大地图中找不到入口，或已接悬赏列表找不到本任务时，共享导航只后台移开鼠标一次，用新截图重新识别。成功路径没有额外截图或等待，失败兜底也不为移鼠标单独增加休眠；返回地图、未知界面和阻断弹窗不触发这项入口兜底。血海入口缺失时直接走下述有界端点拖动，结束时同样移开鼠标，不叠加移鼠标重拍和图标等待。

导航、重启登录、答题和炼丹的完整点击/拖动结束后，默认向已绑定的游戏窗口发送一次 `WM_MOUSEMOVE`，目标为客户区 `(20,20)`；不改变系统真实鼠标位置，不截图、不点击、不枚举其它窗口，也不额外增加 `post_delay`、定时器或休眠。录制回放只在整段结束或停止并释放按键/鼠标后移动一次；时间轴中间不插入避让操作。控制器/窗口失效时停止该操作，不另找窗口。

血海只适配左右端点：孤魂岭用左侧入口 ROI，万世冥阁用右侧入口 ROI。入口已命中时直接使用当前帧点击；未命中且确认地图、普通模式及安全地形时，从同帧地形匹配框中心横向拖向对应端点。拖动为 900ms，端点按住 200ms 后抬起，再用新图识别入口；部分位移仍未命中时，重新核验地图与地形，最多补一次。正常进出关沿用游戏保留的地图视野，下一轮仍只查小区域。不保存跨帧坐标或累计偏移；误入关卡、出现弹窗或地形不明时不继续拖动。

两个方向共用 `town5-02.png` 非交互地形；拖动按下点、轨迹与终点均避开源地图中的关卡按钮。两次修正仍未定位便交原有失败流程。金蟾宝宫的纵向长地图保持原有有限拖动策略。

未发布修正：普通 TemplateMatch 相似度通过资源根目录 `default_pipeline.json` 统一继承 0.83；设置菜单的“继续游戏”文字锚点为 0.80，以兼容小窗口重采样，独立“返回地图”锚点仍为 0.83；差值匹配、颜色范围及 OCR 保留各自标尺。进关使用当帧匹配框中心，原生按住 300ms 后抬起，普通关卡停留 1000ms、悬赏入口停留 2000ms 后移开鼠标；不改录制内部时序。首次进关未确认允许快速重试，最后一次保留至加载等待结束。脚本结束先确认地图，仅在失败时进入共用返回流程；录制包含返回地图但漏点时，也会有界补点并核验，不在正常路径增加菜单识别。

2.4.5 基于上游 v2.4.4（`e1cc891`），相关源码已通过 PR #7 合并。血海端点复用及进关重试调整已于 2026-11-06 安装到测试者的日常客户端，核对程序、资源及个人数据后，由使用者确认手动测试完成。自动检查使用存档图片、Maa 内存控制器和真实 Agent IPC；不将该手测确认扩大为所有角色、关卡及旧版盒子均已逐项验收。正式安装包及校验值以 Release 页面为准。

## 执行模式

导航参考明日方舟 MAA 的 [ProcessTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/1564931cf12514fb5ad1ed35ec09fbdd5960afe9/src/MaaCore/Task/ProcessTask.cpp)、[PipelineAnalyzer](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/1564931cf12514fb5ad1ed35ec09fbdd5960afe9/src/MaaCore/Vision/Miscellaneous/PipelineAnalyzer.cpp) 和 [StageNavigationTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/1564931cf12514fb5ad1ed35ec09fbdd5960afe9/src/MaaCore/Task/Fight/StageNavigationTask.cpp)：目标优先、按顺序尝试相关候选、未命中再展开公共流程、操作后验证实际结果。删除了 `graph.py`、运行用 `graph.json`、全局最短路径规划和每轮全库定位。

```text
本任务目标已可见 → 同帧核验完整入口，以当次匹配框点击
        ↓ 未命中
当前任务相关界面 → 已接悬赏详情 / 任务页 / 当前地图
        ↓ 仍未命中
公共恢复 → 关闭已知面板 / 恢复暂停 / 返回地图
        ↓ 需要跨地图
世界地图 → 南瞻部洲公共入口，或本任务对应洲
        ↓
识别预期结果 → 继续；异常画面 → 有界回退或分类停止
```

现有 `Navigator` 集中持有当前帧。原生 `And`/`Or` 和 ROI 在该帧上核对来源、遮挡及控件，`Context.run_action(name, box=...)` 使用当次匹配框；动作派发前立即清空旧帧和匹配结果，操作失败也不能复用旧坐标。操作后的结果核验图直接用于下一决策，只激活相关候选；加载未就绪时有限重拍。目标或地图已就绪时，不展开公共恢复库。

世界地图与南瞻部洲承担公共中转；能从当前地图、已打开的面板直接完成时，优先使用现有入口。日常活动等实际位于须弥山的界面仍使用须弥山公共流程。悬赏沿用“任务 → 悬赏任务页签 → 对应悬赏详情 → 前往副本”，核对选中页签、详情名称、已接受状态、按钮及浮窗，不自动接取。

点击使用本次识别框。每次拖动、跳转、重连后重新识别，不缓存第一轮的坐标供后续轮次盲点。跨洲流程由资源明确声明，不做运行时或构建时路径搜索。

普通关卡入口把地图及遮挡守卫直接组合进目标节点，导航与点击复用同一结果，避免再套一层目标识别。点击后优先核验场景；若新截图仍明确命中原入口，立即用该帧重试，不等满 15 秒加载超时，进关仍最多三次点击。未知或加载画面只有限等待，不能猜点。场景背景在暂停和设置弹层下也可能命中，因此这两项保留小 ROI 识别；失败及阻断检查只在场景未就绪时展开。纯控制节点显式设置 `pre_delay=0`，移鼠标不新增延迟。

四个悬赏各保留一个稳定入口，公共资源 8 个节点，共 12 个（此前 35 个）；七个普通副本各 5 个节点（此前各 31 个），共享同一轮次实现。当前全部 Pipeline 共 254 个节点。页签、详情名称、已接受状态、浮窗、场景和返回地图核验全部保留；未初始化的悬赏名称条件不匹配任何游戏任务。

入口一次执行完整轮次，失败重试留在该轮内部；只有核验返回地图后才成功返回，原生 `max_hit` 或现有宿主按此计数。`task_catalog.node_links` 同时解析声明的识别/回放依赖，保持原任务 ID、绑定、实例选项和资源安装。游戏管理以同一入口作为初始化及成功边界，用 `next=[]` 结束单轮，继续使用原有重启预算。答题与炼丹保留各自算法。

导航输入使用原生纯动作接口；回放复用现有 `BattlePlay` 实现。MaaFramework 5.12.3 的纯动作接口构造识别 ID 0，Python 自定义动作回调无法据此获取识别详情，因此共享轮次在原 Agent 中调用已有回放实现；没有增加播放器、调度器或输入线程。监测结果按原生 `NodeAttr` 与源码字符串两种格式读取，避免输入释放恰好返回地图时丢失已观察到的战败。

MaaFramework 与 MaaCore 的配置语法不同。本项目不直接照搬 `baseTask`、`@`，也不新增运行时解释器；模板继承在构建阶段解决，运行时使用框架已有的 `And`、`Or`、具名引用和 `next`。

固定控件、文字、弹窗和地形使用 ROI。血海使用已适配端点的入口小区域，偏移导致未命中时先恢复视野；其他可拖动地图仍使用各自的可见区域。ROI 来自资源定义，不把第一轮识别框当成跨轮固定坐标。底层截图仍由 Maa 控制器采集完整客户区：缩小识别 ROI 不等于修复 FramePool 截图延迟。

重新生成公共导航：

```shell
python tools/build_navigation.py
python tools/configure_task_navigation.py
```

旧 `import_navigation_library.py` 只维护历史素材与来源，不再生成旧图规划器或串行探针链。完整 SWF、FFDec 导出、原始日志和开发依赖不随客户端分发。

## 截图预算与验证边界

原则是“两次操作间原则上应只进行一次截图”。截图是完整客户区；ROI 由原生识别器限定，无需 Python 把整图裁成多份。一次截图可识别任务页签、名称、按钮、遮挡并作出一次操作决策，不能把操作前的图拿来核验操作结果。

同版本 MaaFramework 5.12.3、同一内存控制器宝烛录制，在关闭战斗监测且画面立即就绪时，完整单轮由 **19 次降至 5 次**（减少约 74%）：地图 → 主线任务面板（点击悬赏页签）→ 目标悬赏详情 → 副本场景 → 返回地图。真实 Agent IPC 复测同为 5 次。七个普通副本的可见入口路径均为 3 次：地图 → 场景 → 返回地图。场景夹具含合成画布，不替代实机加载验收。

以下额外采样单独统计：加载或返回未响应的有限等待、开启战败重试时的 2 秒监测及既有鼠标操作前检查、异常诊断、原生任务/轮次边界。保留 Maa 原生配额时，两轮示例实际 11 次，包含轮间与最终停止的框架截图；本次没有以另建循环或跨轮缓存图片规避该边界。不能据此承诺任意场景严格每间隔一次截图，或承诺 FramePool 单次取图时间已缩短。

验证覆盖四个悬赏与七个普通副本、错误主线名称、设置/暂停遮挡、移动地图、复活倒计时、失败返回漏点、重试配额、录制变更、人工停止和 Agent IPC。前端 headless 检查确认同一初始化/完成节点保留固定脚本哈希与游戏管理设置。`test_task_generation.py` 校验资源重生成一致性；CI 另运行血海端点恢复与进关 Agent IPC 回归并保存内存画面日志。人工验收状态见本文开头，源码 PR 不等同于发布新安装包。

端点复用的真实 Agent IPC 回归使用独立渲染的血海地图及内存输入：首次恢复视野后进关 3 张图，视野不变的下一轮进关 2 张图，人工偏移并注入一次漏点时 4 张图。后两张正常图分别用于入口决策与场景核验，不额外截图查偏移；这里不含战斗回放、返回和宿主轮次边界。五档地图偏移均验证一次拖动覆盖，以及拖动轨迹不穿过源关卡按钮。幕山同步验证漏点重试。此结果不替代真实游戏加载及 FramePool 延迟验收。

同一幕山夹具、MaaFramework 5.12.3、`OMP_NUM_THREADS=2`，独立进程对比基线 `c6a42bf` 与本轮实现：预热后的正常进关显式 `run_recognition` 调用由 8 次减为 4 次，均为 2 张图；单次测量耗时约 2.52 → 1.75 秒。注入第一次点击未生效时，两次点击间隔约 16.92 → 1.34 秒，整个进关采样由 18 张减为 3 张。这里只统计内存画面的进关流程，不能当作真实客户端平均耗时或完整两轮间隔。

## 失败处理与付费道具

- 关闭战败重试（或普通模式下重试次数为 0）时，脚本回放不启动结果监测，不进行定时截图或鼠标操作前的附加截图，按录制执行至结束；进关与回放结束后的结果/返回核验仍保留。游戏管理的失败重启开关不会单独开启回放监测。
- 开启战败重试时，结果监测默认每次检查完成后等待 2 秒，再进行下一次定时截图，并保留回放起始及鼠标操作前的即时检查。挂机模式实际启用无限战败重试，因此仍开启监测。整轮截图数量并非严格等于回放时长除以 2。
- 普通画面每帧只进行一次统一浮窗检查，Python 入口、原生跳转核验、拒绝复活候选、返回和其它父节点共享结果。确有浮窗时才识别其含义；还魂丹只允许经过布局验证的取消动作，随后等待不再被浮窗遮挡的失败结果；窗口关闭动画不触发快速重复取消，按钮缺失时保留超过十秒倒计时的等待预算。
- 验证码、未知确认框、登录或存档页不由通用导航猜测处理。已知出售确认框只提供取消路线。
- 不认识的画面只做有限次无输入复查；操作失败、没有入口、次数用尽和总时间超限分别报告。加载期间用原生相关候选识别并有限等待，不用全库轮询代替等待。
- 战败先释放输入，返回并确认地图，再按用户设置重试同一轮；失败不增加完成次数。返回地图确认超时仅追加最多两次受保护的失败页返回操作；确认期间晚到的复活框允许一次经过核验的取消，再等待失败结果并继续返回。
- 遇到未识别确认弹窗时，同一帧先检查已知验证码、登录及其他阻断提示。未识别到阻断时，不点击弹窗；回放先释放输入并保留原始原因，开启失败重启后才交给游戏管理恢复同一轮。已识别的阻断、结果歧义及缺失识别资源仍停止。阻断 OCR 并不能保证识别所有验证码或异常弹窗。截图短暂失败先有限复查；持续失败才作为任务失败交接。无任务状态且控制器断连时，前端需连续确认并核验原窗口及进程身份，不能仅凭枚举结果选择窗口。
- 挂机模式不自动开启重启。只有用户开启失败重启，且任务重试耗尽或流程已经确认无法继续时，才交给游戏管理；重启后继续原轮次。
- 人工取消、录制改变、窗口身份或存档核验失败仍停止。游戏管理拥有进程与窗口恢复职责，导航不另启控制器。
