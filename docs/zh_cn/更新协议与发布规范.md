# 更新协议与发布规范

> 2.4.2 合并版已移除自动更新，使用完整客户端手动安装；旧更新器协议及历史命令仅作归档参考。请备份并保留 `recordings/`、`config/` 和个人设置。

适用于 2.3.8 起的统一更新器设计与实现。开发阶段不得据此宣称已上线；代码、离线验证、真实安装验收和公开发布分别记录。本次实现完成后先交用户审阅，再开始实机验证。

## 1. 参考与复用范围

参考明日方舟 MAA 的[更新说明](https://docs.maa.plus/zh-cn/manual/introduction/others.html)及提交 [`d1200888d2afc0cec47d3433160a1c128d28c869`](https://github.com/MaaAssistantArknights/MaaAssistantArknights/tree/d1200888d2afc0cec47d3433160a1c128d28c869)中 `PendingUpdateApplier`、`ResourceIntegrityChecker` 的职责划分：软件/资源版本分开、检查/下载/安装分开、待安装包、完整包修复、受保护数据目录及安装完整性检查。参考流程，不复制 MAA 的 AGPL 实现到本项目。

复用本工程现有目录、`build_update.py` 的资源收集、`build_release.py` 的完整客户端组合、`build_sfx.py` 的手动 EXE、脚本/任务迁移模块及 MFA 的页面与任务互斥。不开设另一个下载服务，不引入二进制差分、账号体系、Windows 服务或新的安装目录结构。

自动完整升级使用与手动 EXE 同源的完整客户端 ZIP，按 MAA 的完整包方式解包安装。不能把任意第三方 EXE 当作更新指令执行。首次安装与人工重装继续提供自解压 EXE。二者程序、资源和依赖必须一致。

## 2. 更新种类与目录边界

| 种类 | 可替换内容 | 安装时机 |
| --- | --- | --- |
| `resource` 小更新 | `resource/`、`agent/`、`interface.json`，保持原三项协议的范围 | 所有任务与录制停止、资源及 Agent 释放后 |
| `client` 大更新 | 完整包清单列出的前端、原生库、Python、启动器、更新器、资源与说明 | 本安装目录的客户端、Agent、录制进程及旧启动器退出后 |

更新检查与下载不改变运行版本；运行任务时只提示更新，不替换文件或抢占输入。第一版不做无提示自动安装。安装需明确的“退出并安装”，下次启动处理待安装包也须显示目标版本及操作。

永久保护根目录 `recordings/`、`config/`、`appsettings.json`、`backup/`、`debug/`、`logs/`、`.local-migrations/`、`.git`、`AGENTS.md` 及未知文件。不能清空安装目录。

小更新保留原三项整体替换语义，因此三项内部的用户改动不是受保护用户库；安装前提示并备份。完整升级仅删除旧安装清单明确拥有且新清单移除的文件。对未知文件同路径冲突拒绝覆盖并提示处理，不把未知内容当旧版本垃圾删除。对于旧清单拥有但已被修改的文件，安装前明确提示将备份并替换。

遵循宿主的运行数据例外：MFA 首次启动会在资源目录生成 `mfa_layout.json`。不在旧安装清单中的这类布局文件保留原字节，不当作资源垃圾删除，也不允许新包静默覆盖；已随旧包分发的布局仍遵守受管理文件规则。`agent/**/__pycache__/*.pyc` 只有能映射到旧清单中 Python 源文件时才视作可再生成缓存，更新时仍纳入备份与回滚，但不要求“允许覆盖修改”的确认。未知缓存、用户扩展及真实源码改动继续受保护。

## 3. 版本与安装记录

- 客户端版本：本项目完整客户端版本，如 `2.3.8`；不是 MFAAvalonia 自身版本。
- 资源版本：现有 `interface.json.version`，完整包记录其内含资源版本。
- 协议版本：整数，第一版统一协议为 `2`；不认识的协议须拒绝安装并提供人工升级说明。
- 渠道：`stable` 正式、`preview` 候选。正式渠道不能安装预发布版本。
- 架构：本项目当前 `win-x64`；架构不匹配拒绝。
- 客户端/资源版本按 SemVer 比较，支持 `2.3.8-rc.1`；不可用字符串大小或把预发布后缀当 0。候选完整包应使用独立版本标识，不通过与正式版同号偷偷替换资产来发布。
- 本地 `client-installation.json` 由完整包构建生成，包含 `schema`、`product`、`client_version`、`resource_version`、`architecture`、`updater_protocol` 及受管理文件的大小/哈希。资源安装不得伪造升级客户端版本。缺少该记录的旧客户端走首次完整安装，不根据资源版本猜测前端版本。
- 安装记录本身不在自身文件哈希表中，以免循环哈希；它必须受包级哈希及事务保护。安装器产生的状态放在 `config/update/` 与 `temp/update/`，不打入发布包。

## 4. 新清单与旧清单隔离

旧 `version.json` 继续仅供旧更新器使用，不能把完整包塞进旧协议或指望旧程序理解新增字段。没有与旧客户端兼容的小更新时保留最后一个兼容清单。

新版读取 `client-version.json`，其结构如下。以下是格式示例，URL 与摘要为占位，不能直接发布：

```json
{
  "schema": 2,
  "product": "MAAZMXY4",
  "channel": "stable",
  "sequence": 1,
  "architecture": "win-x64",
  "client": {
    "version": "2.3.8",
    "resource_version": "2.3.8",
    "min_updater_protocol": 2,
    "package": {
      "kind": "client", "format": "zip",
      "size": 123, "sha256": "<64位十六进制摘要>",
      "urls": ["https://<实际发布地址>/<完整客户端.zip>"]
    },
    "notes": "客户端更新说明"
  },
  "resource": {
    "version": "2.3.8",
    "min_client_version": "2.3.8",
    "max_client_version": null,
    "package": {
      "kind": "resource", "format": "zip",
      "size": 123, "sha256": "<64位十六进制摘要>",
      "urls": ["https://<实际发布地址>/<资源包.zip>"]
    },
    "notes": "资源更新说明"
  }
}
```

`client`、`resource` 至少有一项。完整包和资源包描述不得互换。`max_client_version` 是可选的最高兼容版本（含边界）。不得把与旧前端不兼容的资源投放到旧清单。`min_updater_protocol` 高于本机时仅提示手动升级，不尝试执行。

来源继续使用 GitHub、R2 及现有 CDN。新版来源独立配置，fork 试发布只使用 fork 的清单与资产，不修改上游/R2 共享发布状态。正式与候选使用分开的清单；本地记录渠道与来源身份对应的最高已接受 `sequence`，防止旧镜像使版本倒退。同序号却内容不同应报发布冲突；全部来源失败不能显示“已是最新”。

SHA-256 与文件大小为必填且实际校验，不接受缺少摘要时跳过。HTTPS 校验保持开启。当前协议依赖受信发布源与 TLS；哈希防损坏，不应宣传成独立签名认证。离线导入需要明确选择包并进行同样的结构、架构、兼容性和文件检查。

## 5. 选择更新的顺序

1. 严格验证协议、产品、渠道、架构、清单字段和 URL；未知或损坏清单显示原因。
2. 安装事务未完成时先恢复事务，不开始另一次更新；需要修复时只允许经过验证的完整包。
3. 有更新的完整客户端时优先 `client`，安装其内含资源；若本机资源反而更新，拒绝会降级资源的完整包，要求发布者提供匹配整包。
4. 没有新客户端时检查资源。有新资源且当前客户端在兼容范围内，选择 `resource`。
5. 新资源不兼容时返回“需要客户端升级”，不能只更新 `interface.json`。
6. 正常模式不降级、不按同版本重装。只有显式修复模式允许同版本完整包；修复不能降级已有资源。
7. 成功安装后的客户端再检查是否仍有更高且兼容的资源；不重复安装整包已经包含的资源版本。

## 6. 唯一安装流程与中断恢复

启动器与前端设置页共享 `update_engine` 的版本解析、更新选择、包校验和安装计划。MFA 原生软件/资源更新入口必须转到本项目流程，不能继续自动选取通用 MFA 包覆盖工作台；保留宿主 UI 和任务生命周期能力。

状态：`idle → checking → available → downloading → verified → awaiting_exit → applying → pending_health → complete`；失败转 `failed` 或 `recovery_required`，必须说明下载失败、安装失败、回滚失败之间的区别。

安装前：取得本安装目录独占锁；检查存储空间、路径及包完整性；拒绝路径穿越、绝对路径、链接/重解析点、大小写重名、设备文件、受保护目录、重复文件和异常解压体积；在暂存区完整解压并逐项校验。安装计划不能执行任意命令或迁移脚本。

退出交接：前端须处理未保存脚本、停止任务、结束录制并释放本安装目录的 Agent。独立安装工作进程从暂存的独立运行环境执行，不能依赖即将替换的 Python 或 DLL。旧启动器也须退出，避免它的等待关系占住程序文件。其它目录的助手和游戏不停止。

安装按钮要求任务与录制已由用户停止，并提示先保存编辑内容；不替用户强制停止任务。工作进程只等待本安装目录的程序退出，超时不覆盖。准备好的独立运行时由 `temp/project-update/worker-ready.txt` 指向；标准启动器在读取安装目录的 Python 前检查该记录。恢复期间不要手动清理此目录。若当前安装助手自身的受管理代码或运行时损坏，自动安装拒绝执行，使用完整 EXE 人工修复。

替换：先持久化恢复日志和备份，逐步记录已执行的文件操作；版本记录最后提交。迁移使用当前项目已有脚本绑定/任务配置迁移，保留旧接口定义直到迁移完成。失败时反向恢复；恢复失败保留日志和备份并阻止任务执行，不虚报“已回滚”。进程被杀或断电后，下次启动根据日志恢复，而非重新覆盖一遍。

启动确认：完成替换后启动新客户端，待客户端确认配置与必要服务初始化完成，才记录更新成功。未确认启动保留备份并显示恢复入口；不能仅凭 `Process.Start` 返回成功判定升级成功。安装期间防止第二个实例或录制服务重新占用文件。

## 7. 前端表现

复用现有更新设置页，显示项目客户端版本、资源版本、渠道、检查结果和更新说明；MFA 内核/前端版本作为诊断信息单独展示。

提供“检查更新”“下载更新”“退出并安装”“导入完整包”“查看更新日志”；失败时显示重试/修复入口。启动时检查可关闭；自动下载为可选，默认仅提示。第一版不增加后台定时服务或强制自动安装。

任务/录制运行时安装按钮禁用，保留下载。错误不能被显示成“最新”；没有联网检查的状态显示“尚未检查”。新旧版本、更新种类、下载体积和是否需退出应在安装前可见。默认不展示安装协议字段等开发细节。

## 8. 构建、发布与验收门槛

从规范源码和固定前端构建生成完整 ZIP、EXE、资源 ZIP；统一生成受管理文件清单，不从日常客户端目录打包。新清单仅从真实资产的名称、大小、哈希和实际发布地址生成，不能把占位 URL 推入正式清单。

离线必须覆盖：版本/预发布比较、协议与渠道、镜像过期/冲突、哈希/大小失败、包路径攻击、保护目录、缺失依赖、无绑定脚本、资源兼容性、不同旧版本迁移、同版本完整修复、独占锁、文件占用、每个替换阶段故障回滚、断电恢复、回滚失败与启动确认。前端以无游戏输入的页面/工作进程回归验证状态与互斥。

用户审阅通过后才进入实机：空 test 树下载安装、标准启动器、版本展示、小更新、大更新、个人数据保留、录制/绑定/单轮、失败恢复和多实例隔离。未经此验收不得标为正式可分发。公开后须从实际发布地址重新下载每种面向用户的资产复验。

发布顺序：审阅 → 授权实机 → fork 候选发布/下载复验 → 确认正式版本 → 上游交付。代码提交到 fork 不等于发布资产或更新线上清单。`AGENTS.md` 仅引用本规范和本机边界，不进入安装包。

## 9. 实现与验证入口

- `update_engine/protocol.py`：严格版本、渠道、兼容性和更新种类选择。
- `network.py`、`service.py`：HTTPS 下载、镜像序号、清单冲突、下载与暂存。
- `packages.py`、`validation.py`、`runtime.py`：包内文件清单、路径及逐文件摘要、必需依赖。
- `transaction.py`、`storage.py`：独占锁、备份、持久化操作记录、回滚和启动确认。
- `worker.py`、`processes.py`：独立安装运行时、退出等待和原有任务配置迁移。`agent/task_asset_sync.py` 暴露同一规划函数，避免另写迁移算法。
- `tools/launcher/Program.cs`、`updater.py`：标准启动及异常恢复；恢复失败不能绕过检查直接启动前端。
- `frontend/ScriptStudio/Services/ProjectUpdate*.cs` 与现有版本更新页：一个后端协议，复用宿主任务互斥和退出清理。
- `tools/build_update.py`、`build_release.py`、`build_update_manifest.py`：分别构建资源包、完整包和新清单；`build_launcher.ps1` 生成带构建摘要的新启动器；`build_sfx.py` 保留原有自解压方式。

自动回归入口为 `tests/test_update_*.py`、现有发布/迁移测试和 `frontend/tests/ProjectUpdate/`。这些测试包含模拟进程中断与文件占用，不等价于 Windows 实机安装、启动器恢复或真实断电验收。候选包在审阅阶段可以尚未拥有公开预览清单；此时联网检查应显示失败，不能伪装为“已是最新”，也不能将未发布清单写成已上线。
