# 2.5.3 更新说明

基于 2.5.2-rc.1 的完整客户端安装包（EXE / ZIP），仍采用手动安装，不含应用内自动更新。个人配置、`recordings/`、`config/` 请自行备份。

## 航海寻宝

- **任务正式回归发布包。** 2.5.2 合并上游时 `interface.json` 是拷贝后读取的，导致「航海寻宝」「掉落预判」两个本地任务丢失；本次已把「航海寻宝」补进发布版（发布 81 个任务、自用 82 个）。
- **地图识别改为「先看小地图几列几行、再看白块在哪一格」。** 小地图的格子会被聚类成 4 列 3 行 / 3 列 4 行等，再与 7 套布局的起点格比对；7 套的起点格两两不同，因此白块一格即可定案。
- 修掉两处会「先往下走、进房后又掉头往上」的误判：一是「缺口方向」预筛把小地图已定案的正确答案砍掉，二是进关后用 7×13 礁石图再次改判。
- 换场景改为「还能识别到玩家 → 识别不到玩家 → 玩家重新出现」三步判定，新房间的首帧在「就绪」那一刻才抓，避免抓到上一间。
- 失败判定要求连续 3 帧命中，切场景时整屏偏灰不再被误判成挑战失败；挑战成功后任务直接结束，不再自动点「起航」重进。
- 截图统一走 MAA FramePool（不再用 PrintWindow），按键经 `PostMessage` 直接发给游戏窗口，不抢前台、不动鼠标指针；MFA 日志面板的焦点改指向 `./debug/voyage.log`。

## 生存大冒险

- 选项 OCR 改为取「最长的一段文本」，避免把行首圆点识别成单字（曾把「送唐僧去看大夫」读成「厦」）。
- 事件匹配改用「去掉最差一行后的平均分」，容一次 OCR 失误，不再因为一行糊掉就判「未知事件」并停止点击而卡死。

## 依赖与安装

- VC++ 运行库依赖升级到 14.52.37029.0（原固定的 14.51.36247.0 已无法从微软官方渠道取得），仍按签名与哈希双重校验打包。
- .NET 运行库 10.0.14 不变。安装器为 Inno Setup 7.1.1，与 2.5.2 一致。

## 验证范围

源码按现有 CI 做逻辑回归、前端构建与资源校验；完整包按 EXE/ZIP 两种形态构建并核对 `interface.json` 版本与任务数（81）。游戏内实际跑图、战斗走位与真实窗口尺寸组合仍需实机验证，不属于构建自动保证的范围。
