# 性能与日志优化说明

本次调整集中在小助手的识别调用、停止查询、原生历史与辅助进程生命周期，以及日志占用管理。MaaFramework 原生库和造梦盒子程序保持原样。以下说明对应当前源码实现；尚未进行游戏实机验收，不把离线样本的改善幅度当作完整任务的提速或内存保证。

## 识别与通信

- 常见确认框缩小搜索 ROI；复活短句保留原搜索范围，兼容偏移后的面板。六个省份身份的地形模板改为原生 `Or` 短路匹配，保留完整模板集合和阈值。省份身份只作布尔判断，关卡点击仍使用入口图标的位置。
- 同一帧的城镇、浮窗和复活守卫复用 Maa 已实际执行的正条件结果，不推断短路后未执行的分支。缓存只保留命中和矩形；输入、移动或换帧后失效，不保留截图和调试图。
- 连续像素缓冲直接用于摘要计算，一次回调只计算一次；非连续图像保留兼容回退。
- 等待期间的远端停止查询间隔至少为 50ms；输入前、单轮边界、回放结束和异常交接强制刷新。取消读到后持续生效，Agent 请求仍沿用原来的串行锁。等待中的取消感知最多增加一个查询间隔及 RPC 耗时。

资源由 [导航资源库](../../tools/navigation_library.json) 和 [生成器](../../tools/build_navigation.py) 维护，生成副本随源码更新。省份节点从 `TemplateMatch` 改为 `Or`；自行编写的旧 `param.template` 覆盖需要改用 `any_of` 或重新生成。任务标识、绑定和点击目标未因此改变。

## 内存与生命周期

- 倍速切换仅持有后台输入控制器，每次开启 2 倍和恢复 1 倍各发送两次数字行按键。移除切换阶段的截图、OCR、Resource、Tasker 和截图控制器；保留窗口/进程身份、脚本修订、按键释放、取消及发送失败处理。
- 原有提示消退等待保留。界面中的“已发送”和兼容会话字段 `ready` / `restored` 表示派发或清理完成，不代表识别确认了实际倍率。盒子忽略快捷键等情况仍需使用者检查。
- 只读 `execution_plan` 服务取得独立 JSON 后立即退出，不再陪伴整段导航、回放或重试。
- 宿主只在 Tasker 空闲且相关任务/停止等待已消费结果后调用既有 `ClearCache`。租约覆盖派发到等待完成，清理与新使用者互斥；取消后原生任务仍活动时跳过，下一空闲边界再处理。持续运行的单个原生任务内部历史仍保留，不强制 GC 或修剪工作集。

## 日志管理

“设置 → 性能设置 → 日志清理”包含手动清空和“启用日志滚动刷新”。

- 手动清空先统计数量、大小，再确认删除；任务或录制活动时拒绝执行，不自动停止业务。退出页面会取消未完成的扫描和剩余清理。
- 自动滚动默认开启，所有实例共享选择，立即生效并在重启后保留。关闭会释放自动监听和回收任务，日志继续写入、分块，手动清空仍可使用；重新开启先核算积累的日志。
- `debug/`、`logs/` 中可管理的 `.log` 共用 **64 MiB** 目标。后台合并文件变更通知，按增量元数据维护总量，超限优先删除最旧的已关闭块。普通变化不遍历全部目录，无需逐条日志读取配置；空闲时不持续扫描。
- 前端和相关 Python 日志按约 4 MiB 分块，Maa 沿用原生分块。当前未封块、正在使用或无权限的文件可能使总量超过目标，后续轮转或释放后继续回收；64 MiB 是回收目标，不是对全部活动日志的硬上限。
- 删除前复核路径、文件身份、大小及时间。占用、变化、链接和受保护路径会跳过；截图、任务状态、采集数据、缓存、配置、录制及备份不属于清空范围。

全局选择存于 `appsettings.json` 的 `LogRetention.Enabled`，缺项默认开启。日志器启动时先读取选择，保存为关闭后不会在重启时短暂回收。保存复用宿主配置路径和写锁，保留未知字段、原子替换并留旧内容备份；写入失败保留原状态并显示错误。

以下检查均在独立数据目录完成，没有连接游戏或删除真实用户日志。

局部测量中，100,000 次文件通知被合并为 2 次元数据读取和 1 次初始扫描；合成内存控制器下，倍速准备后的进程 Private Bytes 从约 478 MiB 降至 68 MiB。两者仅代表相应夹具，不推断日常客户端或全任务的固定收益。真实游戏仍需检查不同窗口下的浮窗、跨洲与拖图导航、取消后的输入释放，以及倍速快捷键实际效果。
