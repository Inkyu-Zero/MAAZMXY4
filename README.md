## 这是什么

《造梦西游4》的副本刷取与活动自动化项目，基于 **MaaFramework** 的 Project Interface V2。

本程序做的事：

1. **后台截图**：默认用 MaaFramework 的 `FramePool` 抓取明确选中的游戏窗口，普通任务以短边 720 为识别与回放基准。
2. **后台点击/按键**：默认通过 `SendMessage` 向选中的窗口发送输入。自动回放与录制不同：录制真实操作时仍需让游戏获得焦点，失焦会暂停。

## 主要特性

- **后台运行**：支持窗口被遮挡时截图与输入；请保持游戏窗口非最小化，并先核对预览画面。
- **720p 基准**：常规任务按短边 720 换算坐标；录制和回放仍需保持兼容的游戏布局，不能保证任意缩放与布局都可识别。
- **录制回放**：把你的操作录成 JSON，副本任务里直接重放，不需要写任何代码。
- **脚本工作台**：完整客户端内置“脚本库与录制”“时间轴编辑”两个子标签，支持暂停、阶段标记、框选、批量移动/删除、撤销重做和安全拆分，兼容原有录制及 ZaoMengScript 导入。[使用说明](docs/zh_cn/脚本工具-使用说明.md) · [构建说明](frontend/README.md)。
- **游戏数据库与多状态导航**：原生侧栏查询电脑版装备、道具和 Boss，保留官方/社区/客户端配置来源；七关卡入口增加实际 SWF 状态模板以兼容悬停差分。[资料与验证范围](docs/zh_cn/游戏数据库与导航素材.md)。
- **游戏管理**：可选的失败恢复、按分钟间隔重启及内存维护；维护在任务边界执行，答题异常中断停止并保留日志。[使用说明](docs/zh_cn/游戏管理.md)。
- **挂机与重试**：挂机时持续刷取并重试，直到手动停止或遇到不能自动继续的异常；刷取次数与重试选项由挂机模式接管。仅勾选挂机不会开启盒子重启；失败重启需单独启用，在任务内重试耗尽或确认失败后才介入。
- **ZIP 配置迁移**：在“版本与手动升级”中导出/导入个人配置、绑定与已保存录制，内置压缩和解压，无需 WinRAR 或其它压缩软件。[迁移说明](docs/zh_cn/个人配置备份与迁移.md)。

## 环境要求

- Windows 10（1903 及以上）/ 11，64 位
- 完整客户端自带 Python，无需另装系统 Python；源码构建需自行准备依赖。
- .NET 10 桌面运行时、VC++ 运行库；首次缺少时可使用包内依赖安装脚本，该脚本需要管理员权限。
- 游戏客户端「造梦盒子」；在任务页明确选择窗口并核对预览，不会随意连接枚举到的第一个窗口。
- **请勿最小化游戏窗口**：被其他窗口挡住没问题，最小化会抓不到画面

> ⚠️ 请把整个文件夹放在**普通目录**（桌面、D 盘都行）。
> 如果放在带「低完整性标签」的受限目录里，Windows 会禁止程序抓取其它窗口，
> 表现为启动后提示「抓不到游戏画面」。

## 使用（发布包版，推荐）

### 第 1 步：安装完整客户端

到 [Releases](https://github.com/Inkyu-Zero/MAAZMXY4/releases) 下载
对应版本的 `MAAZMXY4-v<版本>-setup.exe` 图形安装包，或 `MAAZMXY4-v<版本>-win-x64.zip` 完整 ZIP。旧 Release 的 `MAAZMXY4.v<版本>.exe` 仍是自解压包；新的安装器随下一版本提供。

新安装器自带经固定哈希和微软签名校验的 .NET 10、VC++ x64 安装包，以及完整 Python 运行环境；缺失依赖时自动补装，可能需要允许 Windows 权限提示。选择普通目录时自动创建 `MAAZMXY4` 子文件夹，显示最终路径。确认所选目录是本项目旧客户端时，保留配置、录制、绑定、草稿及布局，清理旧程序后安装新版，不备份旧程序；请先退出旧助手。无法确认旧客户端身份时采用新建子文件夹策略，已有无关文件不会被清理。安装完成后由用户自行启动。
从支持 ZIP 迁移的版本升级时，先在旧助手导出个人备份，再解压新客户端、导入备份并重启使其生效。旧版本没有此入口时，按[手动升级说明](docs/zh_cn/脚本工具-使用说明.md#手动升级客户端)迁移，保留 `config/`、`recordings/` 和个人设置。完整客户端 ZIP 与个人备份 ZIP 用途不同，不能互相替代。

安装或解压后目录长这样：

```
MAA造梦西游4/
├─ MAA造梦西游4.exe      ← 双击这个
├─ DependencySetup_依赖库安装_win.bat   ← 缺少 .NET / VC++ 时安装依赖
├─ interface.json
├─ agent/                 ← Python Agent、炼丹模块及只读示例
├─ resource/base/         ← Pipeline、图片、OCR 模型
└─ runtimes/              ← 客户端依赖 + 内嵌 Python 运行时
```

### 第 2 步：运行

1. 先启动游戏「造梦盒子」，进入游戏画面。
2. 双击 `MAA造梦西游4.exe`。
3. 在任务页选择正确游戏窗口，连接后检查预览。
4. 在“脚本库与录制”为需要回放的任务绑定脚本，再勾选任务并设置次数、返回方式等参数。新安装仅提供未绑定的格式示例，需要保存自己的战斗录制。
5. 按任务说明准备地图或活动界面，点“开始任务”。

## 录制回放怎么用

以「伽岚（万世冥阁）」为例：

1. 进入“脚本库与录制”，明确选择游戏窗口，手动进入副本后开始录制。
2. 完成操作后停止录制并保存，可在时间轴中调整事件和总时长。
3. 把保存的脚本绑定到“伽岚（万世冥阁）”。
4. 在任务设置中选择录制是否包含返回地图，再设置次数并开始任务。

录制从进入副本后的战斗画面开始。若录制已经包含返回地图动作，将“录制内容是否包含返回地图”设为“是”；只录了战斗则选“否”，由任务负责退关。两种方式都会确认返回地图。

### 导航重构（开发中，尚未发布）

当前开发版基于上游 2.4.4，移除最短路径规划，采用 MAA 的目标优先和相关候选流程。公共导航节点从 569 个减至 125 个；需要时通过世界地图、南瞻部洲和已标定的洲入口中转，点击后核验。保持战败重试、付费弹窗取消、挂机与重启的原有分工，并修复滚动地图 ROI 覆盖空隙。

血海首次需要恢复视野时只拖一次至目标端点，后续正常轮次只检查入口小区域；点击后仍明确停留在原入口时，使用新截图重试，不等待完整加载超时。详见[导航实现、性能与验证范围](docs/zh_cn/通用导航迁移与失败重试说明.md)。离线、Maa 内存控制器及真实 Agent 通信验证与使用者手测分别记录，测试版已安装，正式发布仍以 Release 页面为准。

### 放弃并重录（下一版本，尚未发布）

录制区第一排是“开始录制”“停止并编辑”，第二排是“暂停”和红色 **“放弃本次录制”**，四个按钮等宽。放弃后清空本次未保存内容，停留在录制区，再点击“开始录制”即可录下一段；可勾选“双击放弃本次录制”，仅改变该按钮的触发方式，不影响快捷键。开始倒计时、录制、暂停和继续倒计时期间均可使用；已停止但尚未保存的录制草稿，也可从时间轴上方放弃。

无需命名、保存或二次确认；游戏窗口选择和倒计时设置保留，倒计时设为 `0` 可立即开始。已保存脚本和任务绑定不变；被放弃的内容不生成恢复草稿，无法撤销。

## 使用（源码版）

需要自己准备运行环境：

1. 按[前端构建说明](frontend/README.md)构建本项目固定版本的定制 MFAAvalonia。
2. 按[运行时准备工具](tools/setup_runtime.py)准备内嵌 Python；完整发布包已包含该运行时。
3. 使用 `tools/build_release.py --client` 从 `assets/interface.json`、`assets/resource/`、`agent/` 和明确指定的构建产物组合客户端。
4. 不要把日常使用目录整体打包，也不要用通用 MFA 前端覆盖本项目的定制页面。

源码准备运行时时，需包含 MaaFramework Python 绑定、NumPy、pynput、Pillow、OpenCV 等依赖；具体清单以 `tools/setup_runtime.py` 和 `tools/runtime_check.py` 为准。`python tools/runtime_check.py` 检查源码树的内嵌运行时；最终包还须使用自己的解释器做功能探针，不能借用开发机环境。炼丹必须实际加载模板并执行图像匹配，仅导入模块不会触发所有依赖。[打包与依赖验收](frontend/README.md#发布前依赖检查)。

改完 Pipeline 后记得校验：

```bash
python tools/check_adventure.py     # 生存大冒险题库与事件自检
```

## 常见问题

**Q：双击 `MAA造梦西游4.exe` 没反应，或者提示缺少 .NET？**

客户端是 .NET 10 应用，第一次在新电脑上用需要先装运行库：

1. 右键同目录的 **`DependencySetup_依赖库安装_win.bat`**，选择“以管理员身份运行”。
2. 它会自动装 **.NET 10 桌面运行时** 和 **VC++ 2015-2022 运行库**（优先用 `winget`，没有就自己下载安装包）
3. 装完再双击 `MAA造梦西游4.exe`

如果脚本提示没有 `winget`，它会走下载安装；下载失败就手动装：
<https://aka.ms/dotnet/10.0/windowsdesktop-runtime-win-x64.exe>

**Q：提示「抓不到游戏画面」？**

1. 确认游戏窗口标题含「造梦盒子」，且没有最小化。
2. 确认整个文件夹不在带「低完整性标签」的受限目录里
   （管理员 PowerShell 执行 `icacls "<目录>" /setintegritylevel (OI)(CI)Medium /T /C` 可修复）。
3. 如果游戏以**管理员权限**运行，本项目也要用管理员权限运行。

**Q：点关卡没反应，或者点进了别的关卡？**

鼠标悬停在关卡上会触发高亮贴图。本项目已经用「点到就移开」的方式规避，
如果仍然偶发，把「刷取次数」设小一点先观察，或换用录制回放版本。

**Q：回放和录制时的手感不一样？**

回放依赖游戏帧率、窗口布局和系统负载，不能保证固定的输入误差。先检查录制中按住与释放是否配对、总时长是否正确，并用单轮任务验证；需要时在时间轴中增加操作间隔。

**Q：保存了录制，任务仍提示未绑定？**

在“脚本库与录制”的对应脚本行点击“绑定任务…”，勾选目标任务并保存。当前版本使用任务绑定，不依靠旧版“回放文件”下拉；另存为新脚本不会自动更改原任务绑定。

**Q：九转炼丹报 `No module named 'cv2'`，是不是脚本丢了？**

这是内嵌 Python 缺少 OpenCV。2.4.3 早期安装包曾出现这一问题：4 个炼丹 Python 文件和 11 张模板齐全，但图像匹配时才会延迟加载 `cv2`，因此“模块能导入”或“任务能显示”不代表能正常炼丹。

安装系统 Python 或运行 .NET / VC++ 依赖安装脚本不能补齐包内的 `cv2`。请使用包含完整运行依赖、通过验收的客户端包；同名版本附件也可能被重新上传，以实际资产和检查结果为准。开发者须检查包内 `runtimes/python/Lib/site-packages/cv2/` 及本机扩展，构建和验收步骤见[前端说明](frontend/README.md#发布前依赖检查)。
